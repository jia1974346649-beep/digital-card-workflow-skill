# 公开边界与作品真实性

## 我们公开什么

公开用户主导的研究、取舍、角色设计、交互反馈、迭代修复、验证方法和交付组织方式。将经验写成可复用 skill、匿名案例与模板。

截图中的最初目标过程也纳入：识别参考产品、梳理公开能力、拆解用户任务、确定范围与依赖。这里用新写的目标卡和流程图呈现，不直接发布任务侧栏或原始会话。

早期跨端探索与后期聚焦的企业名片流程分别说明。被探索过、写过原型的能力，不自动列为当前业务产品已经提供的功能。

## 什么没有进入这个仓库

- 原业务仓库、其 Git 历史、数据库迁移、发布包与生产脚本。
- 公司及客户的名称、品牌、Logo、人员、头像、联系方式、地址与业务资料。
- 原始截图、会话导出、内部手册、设备截图、二维码和平台授权画面。
- 环境文件、凭据、真实域名、服务端地址、应用标识、租户与云资源标识、回执与本地路径。

公开图从零用通用图形绘制，无照片、品牌资产或真实扫码内容。内部手册使用过的局部浅模糊截图不在本仓库中；模糊不能替代公开场景中的资料排除。

## 作品如何署实

用户负责目标、使用场景、优先级、方案选择、体验反馈和交付要求；AI 协作完成研究、实现、自动化与整理。既不抹去人的主导作用，也不把协作生成的全部代码说成独立手写。

案例承认出现过的失败：浏览器外观不等于原生输入验证，头像上传不等于访客可见，接口响应不等于实际消息送达。未验证的路径保持未验证，不沿用旧版本的结果宣传新版本。

这里没有宣称原项目已全部通过手机与电脑验收、已正式发布、在某个时间盒内完整交付，或达到特定商业成果。

## 发布检查

1. 在新的干净目录撰写，只加入 `publication-manifest.json` 中列出的文件。
2. 对文本、链接、SVG 内容、文件名、staged tree 和所有 Git refs 的历史对象做检查。
3. 私有禁止词表存放在发布目录之外；检查只报告类别、相对文件与行号，不回显原值。
4. 逐图检查公开示意，确认没有原品牌、私人信息、真实二维码或后台地址。
5. 清点将上传的仓库与可见范围。发布账号通过平台本人的认证步骤，不索取密码或令牌。

自动扫描只能发现已配置的规则，不能证明资料一定没有关联风险。保留人工复核与内容归属核对，不把“扫描通过”写成绝对保证。
