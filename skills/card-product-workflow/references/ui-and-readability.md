# UI 一致性与易读性

## 何时使用

用户反馈字体小、排版乱、实现与方案不符，或本人页与访客页不一致时使用。先明确问题发生在哪个入口、设备、字号和内容状态。

## 将感受转成检查条件

“精致”应落实为层级、留白、对齐、颜色、组件与操作一致性。“大字”应落实为主要信息可读、长内容可换行、按钮不遮挡和页面不溢出。

采用同一份虚构资料比较方案和实现，避免样例不同导致误判。

## 保持四处一致

- 本人查看与编辑后的实际效果。
- 访客打开的完整名片。
- 发送页中的名片预览。
- 聊天中的缩略卡片。

完整页与缩略图的信息密度可以不同。缩略图优先展示头像、姓名、组织和职位等关键识别信息，不把整页小字压进图片。

## 大字不等于整体等比放大

分别确定姓名、联系方式、标签、说明和按钮的层级。长地址与邮箱应有可控换行，电话号码不因局部溢出变得难以辨认。

标准与大字模式都检查窄屏、长内容、空字段和无头像。字号状态不应造成分享封面错用缓存，也不应改变业务权限。

## 原生输入框的特殊边界

提示文字居中，不证明输入文字也居中。浏览器中的输入行为也不能证明目标原生渲染器表现正确。

优先让外层承担背景、边距与触控区域，内层保持正常文本行。避免用异常大的文本行高修饰原生输入，造成填写前后基线不同。

若整个外层需要可点选聚焦，明确焦点状态与失焦竞态；旧字段的失焦不能清掉刚切入新字段的焦点。

不要每次输入都重建控件或反复切换焦点，以免影响光标、中文组合输入和键盘。

## 至少检查的输入状态

- 空值提示与真实输入。
- 中文、数字和拉丁文本。
- 聚焦、切换字段和失焦。
- 清空、重填与重新进入。
- 提交等待期间的禁用状态。
- 标准／大字模式及相关原生渲染器。

模拟器只能触发程序化事件时，记录该限制；不能写成真实键盘动作已经验证。

## 视觉证据

截图必须注明浏览器、原生夹具或真实设备来源。截图清楚不代表网络、权限或实际收件已经验证。

检查完整页及重点区域，避免只看上半屏。桌面截图移开鼠标，去除浮窗、提示和与产品无关的界面。

## 公开示意

从虚构数据重新制作人物、组织和联系方式。内部用的浅模糊图不直接公开；除了文字，还要检查头像、品牌、二维码、浏览器地址和文件元数据。

## 完成条件

所选视觉方向与实际页面逐项对照，相关状态有可查看证据；尚未覆盖的设备和入口明确列出，不用测试数量代替视觉判断。
