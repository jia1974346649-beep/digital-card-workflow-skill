# 验证证据与交付状态

## 何时使用

准备上传、声称修复完成、更新手册或整理作品集时使用。先确定要证明的行为，再选择证据，不能从测试数量反推整个产品可用。

## 证据类型各自证明什么

| 类型 | 可以支持 | 不能直接支持 |
| --- | --- | --- |
| 静态检查与逻辑测试 | 规则、状态分支、数据转换 | 原生显示与真实送达 |
| 浏览器布局 | 指定样例与宽度的排版 | 原生输入、设备键盘与平台行为 |
| 原生离线夹具 | 特定渲染器与控件表现 | 真实网络、真实权限与收件 |
| 真实接口检查 | 指定环境下的服务结果 | 客户端呈现与端到端体验 |
| 实机操作 | 该设备、入口与状态的行为 | 其他设备或后续产物 |
| 实际收件与打开 | 指定发送链路的可见结果 | 所有分享方式均正确 |
| 平台状态核对 | 上传、体验、审核或发布状态 | 业务功能已经验收 |

这些证据是互补维度，不是单一分数。模拟器失败也要区分产品缺陷与工具环境不可用。

## 每项记录的最小信息

- 产物标识与内容摘要。
- 测试入口、身份和运行环境。
- 数据为虚构还是受控真实数据。
- 操作、预期与实际结果。
- 证据位置、检查时间和已知限制。
- 通过、失败、阻塞或未验证。

旧产物的结果不能替代新产物。修改后的范围不同，可以据依赖关系复用逻辑判断，但不能把旧实机记录改名当成新验收。

## 复测应围绕风险

复现用户报告的具体状态，再检查相关反例。输入问题看填写前后，分享问题看对方实际收到，缓存问题看失败后恢复和旧请求晚到。

不要为凑数量重复相同检查。修复改变了共享组件或权限边界时，再扩展受影响入口。

工具返回成功后，检查真实画面或业务结果。空白截图、超时和无法到达页面不能计为验收通过。

## 冻结与部署

冻结待上传产物，记录摘要，确认检查针对同一份内容。避免检查后继续手工修改包却沿用旧结论。

部署涉及权限或数据结构时，准备可检查的变更、回滚办法和回读步骤。临时访问在完成后清理，不因部署困难留下长期宽权限。

## 上传不等于正式发布

分别记录构建完成、上传成功、体验版已设置、已提交审核、审核结果和正式发布。只操作用户授权的状态转换。

已有持续上传授权时不反复询问同一许可；但平台要求的本人登录或原生确认仍由用户完成。工具明确拒绝或任务过期时，按该工具规则处理，不暗中重复提交。

异步上传保存任务状态，核对原任务结果，避免重复上传。没有平台证据时不宣称体验版已更新。

## 文档与公开说明

手册中的功能说明应与声明的产物一致。截图可以解释操作，但不是网络、权限和真实收件的替代证据。

作品集应说明用户主导与 AI 协作的分工。保留未完成检查，不把局部成功包装成全部实机通过或全链路上线。

## 结束前核对

变更、检查、限制和当前平台状态能够对应；用户能找到产物；没有未说明的失败；测试用数据与临时访问已按范围清理。
